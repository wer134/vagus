## 1. 원칙

`FIX_PLAN.md` §0.2와 `ROADMAP.md` §1을 그림에도 그대로 적용한다.

1. **모든 도판은 결과 JSON에서 스크립트로 생성한다.** 손으로 숫자를 넣은 그림은 손으로 고친
   결과 파일과 같은 종류의 결함이다. 대시보드의 `EMBEDDED_*` 상수가 바로 그 사례다.
2. **도판은 측정 조건을 달고 다닌다.** E-4가 결과 JSON에 넣은 `git_commit` · `seed` ·
   `contract`(obs/action/reward/sim 버전)를 캡션에 그대로 싣는다. 조건 없는 그림은 P1과 같은
   결함 — 나중에 어느 자로 잰 건지 알 수 없다.
3. **나쁜 결과를 그릴 수 있어야 한다.** 잘 나온 경우에만 말이 되는 차트는 틀린 차트다.
   `cicddos_validation_v2_curve.png`가 좋은 선례다 — "시간이 지나도 베이스레이트를 못 넘는다"를
   그림으로 증명한다.
4. **철회된 수치는 다시 그리지 않는다** (§5).

여기에 차트 자체의 규칙을 더한다 (`dataviz` 스킬):

5. **이중 축 금지.** 스케일이 다른 두 측정은 차트 두 개나 small multiples로. TTR과 부수 피해를
   한 축에 얹고 싶은 유혹이 정확히 이 경우다 (F2).
6. **색은 역할로 고른다.** 크기 비교 = 순차(한 색조), 정체성 구분 = 범주(고정 순서), 하나가
   주인공 = 강조(1색 + 회색). 범주 색은 순서대로 쓰고 순환시키지 않는다.
7. **팔레트는 눈으로 판정하지 않고 검증기를 돌린다** (`dataviz/scripts/validate_palette.js`).
8. 계열 2개 이상이면 범례는 항상, 4개 이하면 직접 라벨도 함께. 색만으로 정체성을 주지 않는다.

## 2. 도구와 구조

### 2.1 렌더러 두 개, 팔레트 하나

| 용도 | 렌더러 | 근거 |
| --- | --- | --- |
| 문서 도판 (README·cowork·논문) | **matplotlib** → SVG + PNG | 이미 의존성에 있고 기존 곡선을 만든 도구. 정적이면 충분 |
| 대시보드 | **Chart.js** (기존 유지) | 이미 들어가 있고 호버·필터가 필요 |

두 렌더러가 각자 색을 고르면 반드시 어긋난다. **`experiments/figures/palette.py` 하나를 단일
출처**로 두고, matplotlib은 직접 import, 대시보드는 이 파일에서 생성한 CSS 커스텀 프로퍼티
(`--series-1` …)를 읽는다. 값은 `dataviz/references/palette.md`의 검증된 기본 팔레트를 그대로
채택하고, 채택 시점에 검증기를 한 번 돌려 결과를 파일 주석에 남긴다.

### 2.2 배치

```
experiments/
├── figures/
│   ├── palette.py          # 검증된 팔레트 단일 출처 (+ 라이트/다크 슬롯)
│   ├── figspec.py          # 캡션·조건 스탬프·저장(SVG+PNG) 공통 헬퍼
│   └── out/                # 생성물 (커밋함 — README가 참조)
└── make_figures.py         # 결과 JSON → figures/out/*.svg|png 전부 생성
```

`make_figures.py`는 `reproduce.sh`의 마지막 단계로 편입한다. 결과가 갱신되면 그림도 같은 실행에서
갱신되므로 둘이 어긋날 수 없다.

### 2.3 라벨 언어 — 이미지 안은 짧은 영어, 설명은 마크다운 캡션

기존 `_plot_learning_curve()`는 한글 라벨을 쓰려고 OS 폰트(맑은 고딕/AppleGothic/나눔고딕)를
찾는다. Linux CI에는 셋 다 없어 두부 문자가 난다. **이미지 안에는 축·범례만 짧은 영어/숫자로
넣고, 해설은 마크다운 캡션에 한글로 쓴다.** 폰트 의존이 사라지고 그림 재사용도 쉬워진다.

## 3. 도판 카탈로그

각 도판은 `무엇을 읽게 할 것인가(job) → 형태(form) → 색 역할(color job)` 순으로 정했다.

### F1. TTR 분포와 물리 하한 — `ttr_distribution`

- **Job**: 분포, 그리고 "거의 하한에 붙어 있다"는 사실
- **Form**: 세로 막대(TTR 4~11 도수) + **하한 참조선** (cost 적용 후 SLA 회복까지 4틱,
  `metric_generator` 자가 테스트가 재는 값) — 계열 1개이므로 범례 없음
- **Color**: 순차 1색조 + 참조선은 회색 점선
- **Data**: `stress_50ep.json.results[].ttr` (현재 4:1 5:1 6:21 7:17 8:5 9:2 10:2 11:1)
- **왜**: 대시보드의 2/3/4/5 분포를 대체한다. "TTR 6.86"이 나쁜 게 아니라 **하한 근처**임을
  한 장으로 보여준다.

### F2. 절제 — TTR은 같고 부수 피해만 늘어난다 — `ablation_pair`

- **Job**: 세 모드 비교. 핵심은 "combined가 analytics_only 대비 얻는 게 없다"
- **Form**: **가로 막대 두 패널(small multiples)** — 좌: 평균 TTR, 우: 부수 피해/ep.
  범주 순서 고정(analytics_only / maml_only / combined). **이중 축 절대 금지** — 이 그림이
  로드맵에서 가장 유혹이 큰 자리다
- **Color**: 패널별 순차 1색조. 동률인 두 막대(7.08 / 6.90)는 직접 라벨로 수치 노출
- **Data**: `ablation_study.json.results[*].{avg_ttr, wasted_actions_per_ep}`
- **왜**: 이 프로젝트의 가장 중요한 결론(복구는 Analytics가 한다)이 그림 한 장이 된다.

### F3. 정책 붕괴 — `policy_actions`

- **Job**: "MAML은 한 가지 행동만 한다"를 즉시 보이게
- **Form**: 체크포인트별 **가로 누적 막대**(행동 선택의 부분-전체). MAML은 한 덩어리,
  PPO는 6조각 — 대비가 그림 자체로 말한다. 옆에 엔트로피 **스탯 타일**(0.00 bit vs 1.70 bit)
- **Color**: 범주 팔레트 고정 순서, 행동 6종이라 상한(8) 이내. 범례 + 4개 이하 직접 라벨
- **Data**: `policy_check.json.{ppo,maml}.on_policy_counts`
- **왜**: P8은 지금 표로만 있다. 이 그림은 숫자를 몰라도 읽힌다.

### F4. 성공 50%는 정책이 아니라 우연 — `offline_by_link`

- **Job**: 에피소드별 성패가 **링크에 따라 갈린다**는 것
- **Form**: 링크별로 나눈 **스트립/도트 플롯** (x=TTR 로그 또는 구간, 점=에피소드).
  r3-r4는 2~5에 모이고 r1-r4는 전부 200(타임아웃)에 쌓인다
- **Color**: 강조 형태 — 타임아웃 점만 status(경고), 나머지는 기본 1색조
- **Data**: `offline_eval.json.{baseline,fewshot}.ttr_list` + `eval_links`
  (MAML: 2.5 / 200 / 4.0 / 200 … 교대)
- **왜**: "성공률 50%"라는 숫자의 실체를 드러낸다. 표로는 절대 전달되지 않는다.

### F5. 우회의 대가 — `routing_detour`

- **Job**: cost를 올리기 전/후 링크별 부하 변화
- **Form**: **덤벨**(before → after, 링크 6개) — 전형적인 before/after per item
- **Color**: 1색조 2단계(before 연함 / after 진함), 화살표 방향으로 증감
- **Data**: `metric_generator.get_link_loads()`를 스크립트가 직접 호출 (r3-r4 → 100 적용 전후).
  결과 JSON이 아니라 시뮬레이터를 부르는 유일한 도판 — **재현 코드를 캡션에 명시**
- **왜**: B-1이 왜 필요했는지(우회가 공짜였다)를 설명하는 가장 빠른 방법.

### F6. 탐지기 rolling F1 vs 베이스레이트 — `cicddos_curve` *(기존 이식)*

- **Job**: 시간이 지나도 자명한 베이스라인을 못 넘는다
- **Form**: 선 + **베이스레이트 참조선**(점선) + cold-start 구간 음영. 현재 형태 유지
- **Color**: 1색조 + 회색 참조선 + 중립 음영
- **작업**: `validate_security_detector.py` 안의 플로팅을 `make_figures.py`로 옮기고
  한글 라벨 제거, 팔레트 통일. **결과 자체는 재측정 없이 그대로** (CSV 없음)

### F7. 탐지기 혼동 행렬 — `cicddos_confusion`

- **Job**: TN/FP/FN/TP 크기 비교
- **Form**: 2×2 **히트맵** + 셀 값 직접 표기
- **Color**: 순차 1색조 (격자 크기 비교의 표준)
- **Data**: `cicddos_validation_v2.json.metrics.confusion_matrix` = `[[1880,1933],[2234,2652]]`
- **왜**: "F1 0.56"이 "전부 공격 예측으로 무너진 것은 아니다"(BENIGN 3,813 중 1,880 정답)를
  같이 보여준다 — 불리한 수치를 맥락과 함께 내는 이 리포의 기조에 맞는다.

### F8. OODA 폐쇄 루프 구조도 — `ooda_loop` *(차트 아님)*

- **Form**: 인라인 **SVG 다이어그램**. Observe→Orient→Decide→Act→Evaluate와 각 단계의 실제
  구현 함수, 그리고 **어느 계층이 실제로 일하는지**(Analytics override 경로를 굵게)
- **왜**: `PROJECT_OVERVIEW.md`의 ASCII 다이어그램을 대체하고, 절제 결론과 구조를 잇는다
- 작성 시 `artifact-diagramming` 가이드를 따른다

### F8 이후 — 학습·테스트 도판 (2026-09-13 추가)

앞의 F1~F8은 **이미 내린 결론을 설명하는** 그림이다. 아래 T1~T4는 **아직 열려 있는 질문에
답하기 위한** 그림이라 우선순위가 더 높다.

현재 학습은 아무것도 남기지 않는다 — MAML은 `meta_loss`를 20 iter마다 stdout에 찍고 버리고,
PPO는 `verbose=1`로 SB3 표를 찍고 버린다. 콜백도 로그 파일도 없고, `*.meta.json`은 **최종
체크포인트 상태만** 기록한다. 그래서 "붕괴했다"는 알지만 "언제 붕괴했는가"는 답할 수 없다.

#### T1. 학습 중 붕괴 곡선 — `train_collapse`

- **Job**: 정책이 **언제** 탐색을 그만두는가. P8의 유일한 미해결 질문
- **Form**: 선 그래프 **패널 2개** — 위: 행동 엔트로피(bit), 아래: 최빈 행동 비율 +
  붕괴 임계선 0.8. 스케일이 다르므로 **이중 축 금지**. MAML/PPO 2계열이므로 범례 + 직접 라벨
- **Color**: 범주 슬롯 1·2 (blue/orange), 임계선은 회색 점선
- **Data**: 신규 — `train()`에 주기적 정책 프로브 콜백 → `results/train_curve_{maml,ppo}.json`
- **왜**: "붕괴했다"가 "iter ~N에서 붕괴하고 회복하지 못했다"가 되면, A-3(보상)이냐
  A-4(커리큘럼)이냐를 가르는 근거가 된다. 지금은 그 데이터를 매번 버리고 있다

> **손실 곡선은 그리지 않는다.** 실측 `meta_loss`는 +0.0069 / +0.0073 / +0.0276 / −0.0012 …
> −0.0141 / −0.0376 / −0.0066 / −0.0265 으로 **0 주변 진동이고 추세가 없다** — advantage를
> 정규화한 REINFORCE 손실이라 당연한 결과다. 그리면 과학적으로 보이지만 아무 의미가 없다.
> **손실이 아니라 행동을 그린다.**

#### T2. 체크포인트 이력 스코어보드 — `checkpoint_history`

- **Job**: Track A의 각 변경(A-1 관측 v2, A-3 보상 v2 …)이 실제로 붕괴를 풀었는가
- **Form**: 체크포인트를 시간순으로 놓은 **소형 다중** — 엔트로피 / 최빈 비율 / TEST 성공률.
  변경 지점(sim 버전·계약 버전 전환)을 축에 표시
- **Color**: 순차 1색조 + 붕괴 판정은 status(경고) 마커
- **Data**: **이미 존재** — `agents/*.meta.json`에 commit·seed·계약 버전·붕괴 통계가 있다.
  모으기만 하면 된다
- **왜**: Track A의 진척을 한 장으로. 지금은 재학습할 때마다 결과가 대화 속으로 사라진다

#### T3. seed 분산 — `seed_spread` *(A-7 이후)*

- **Job**: 결과를 seed 하나가 끌고 가는지
- **Form**: seed별 점을 **전부** 찍는 도트 플롯 + 평균선. 평균±표준편차 막대만 그리지 않는다
- **왜**: A-7이 seed 5개를 요구한다. 평균만 그리면 "단일 seed 수치 금지" 규칙의 정신을 배신한다

#### T4. 주장–검증 매핑 — `claim_coverage` *(테스트 쪽 유일한 도판)*

- **Job**: `ROADMAP.md` §0의 주장 각각을 **무엇이 자동으로 검증하는가**
- **Form**: 주장 × 근거유형(자가 테스트 / 결과 파일 / 없음) **매트릭스**. 대부분 "없음"으로
  나올 것이고 **그 공백이 정보다**
- **왜**: §0 표는 지금 수작업으로 유지된다. 장식이 아니라 정직성 인프라

#### 테스트 시각화에 대한 판단 — 대체로 하지 않는다

- 자가 테스트 9개는 전부 pass/fail이다. 항목이 7개를 넘고 각각 의미를 가지므로 **표가 맞는
  형태**이고, `selftest.sh`의 터미널 출력이 이미 그 표다. 차트로 만들어도 정보가 늘지 않는다
- 의미 있는 건 **추세**(언제부터 깨졌나·소요 시간·플레이키)인데 **CI(E-2)가 없어 이력 자체가
  없다.** 그릴 데이터가 없다 — E-2가 들어가고 실행이 쌓인 뒤에 다시 볼 문제
- 당장은 차트보다 **CI 배지** 하나가 실용적이다
- TensorBoard 류 학습 대시보드는 과하다 — 학습이 5분이고 체크포인트가 3개인 규모다

## 5. 시각화하지 않을 것

**그리지 않는 것도 결정이다.** 그림은 주장을 되살린다.

| 대상 | 이유 |
| --- | --- |
| `sample_efficiency.json` 곡선 | 근거가 된 "500배 샘플 효율" 문구가 2026-09-06에 삭제됐다. 데이터는 남기되 **그리지 않는다** |
| `summary.json`의 baseline (200.0) | 미학습 랜덤 정책, 30 에피소드, 다른 측정 경로. 비교 차트에 올리는 순간 철회된 주장이 부활한다 |
| sim_v1/v2/v3 TTR을 한 축에 얹은 추이 차트 | **서로 다른 자로 잰 값**이다 (2틱 vs 1틱 vs 라우팅 변경). 한 축에 놓으면 "개선/악화"로 읽힌다. 전/후 병기는 **표**로만 하고, 굳이 그린다면 변한 것은 자이므로 "사이클당 틱 수"를 그린다 |
| 폐쇄 루프 TTR vs 오프라인 TTR 비교 | 측정 경로가 다르다. AUDIT P1이 잡은 실수를 그림으로 반복하는 꼴 |
| 정책 붕괴 체크포인트의 "성공률" 단독 막대 | F3(행동 분포)와 **반드시 같이** 낸다. 성공률만 떼면 상수 정책이 유능해 보인다 |
