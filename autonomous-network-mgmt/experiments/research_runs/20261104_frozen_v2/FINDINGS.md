# 복구 완료·원상복귀 제어 연구 결과

이 보고서는 `test.json`의 1080개 시행을 원시 기록에서 집계했다. 정책 9개, 환경 6개, 독립 seed 20개를 모두 포함한다.

## 연구 범위와 출처

- 구현 출처: `new_from_spec_snippet`. 제공 명세·코드 조각을 바탕으로 새로 구현한 합성 실험이다.
- 관련 문헌은 설계 비교·조사 근거이며, 원저자의 코드나 데이터로 논문 수치를 재현한 결과가 아니다.
- 실제 장비 성능, 표준 전체 준수, 신규성 또는 모든 환경에서의 우월성을 입증하지 않는다.
- manifest SHA-256: `9d68a2a89b03bbb28b22de218dde384eca4d818b8ed6611c8d8c19a397b97768`
- source-set SHA-256: `2d9a36209c4fa2f916893a6f2c4d72770a43797b850c7679b7dfe47933ddab25`
- 고정 계약: `observations_only_controller;paired_exogenous_v1;settled_safe_completion`
- seed: `1000, 1001, 1002, 1003, 1004, 1005, 1006, 1007, 1008, 1009, 1010, 1011, 1012, 1013, 1014, 1015, 1016, 1017, 1018, 1019`

## 지표 해석

false_completion·unsafe_restore·timeout 비율의 분모는 해당 정책의 전체 시행이다. `declaration_delay = declared_tick - true_recovered_tick`이며 음수는 조기 선언을 뜻한다. 두 시각 중 하나라도 없으면 결측으로 유지한다. 지연 평균은 두 시각이 관측된 시행에만 적용되며 timeout을 0으로 치환하지 않는다. 지연만 낮다는 이유로 정책이 우수하다고 판단할 수 없다.

overload_area는 관측 종료까지 각 링크의 `max(utilization - 1, 0)`을 모두 합한 tick 적분이다. command_count는 명령 횟수이며 완료 선언 이후도 정해진 horizon까지 추적한다.

표의 전체 평균과 각 환경 결과를 함께 해석해야 한다. 실패·timeout·보정 무효 조건을 제외해 승자를 선택하지 않았다. 테스트 결과를 보고 정책이나 임계값을 다시 선택하면 이 동결 평가와 구분되는 새 실험이 필요하다.

도판은 `research_findings_plot.py --input <평가.json> --output-dir <새 디렉터리>`로 생성한다. 세 패널의 축 단위는 각각 실패율(%), 선언 지연(tick), 과부하 적분이며 이중 축을 사용하지 않는다.
